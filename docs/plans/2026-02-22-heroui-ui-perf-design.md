# HeroUI 迁移与轻盈简约 UI/启动优化设计

**目标**
- 将现有 NextUI 迁移至 HeroUI，消除弃用依赖并保持组件能力。
- 重构页面排布与按钮样式，达成「轻盈清爽」的现代简约观感。
- 优化启动过程与首屏渲染路径，缩短可用时间并降低首屏压力。

**范围**
- 仅涉及 editor-web（WebView 页面）与构建产物。
- 不改变 Android Native 层逻辑，仅重打包资源。

---

## 架构与组件

**总体结构**
- 维持 React 单页结构，入口 `main.js`。
- UI 组件从 `@nextui-org/react` 替换为 `@heroui/react`。
- 继续使用 CodeMirror，保留原有文件树与编辑器逻辑。

**组件分区**
- Sidebar：搜索与文件树（Listbox）。
- Topbar：标题/状态 + 操作区（分组按钮）。
- Editor：CodeMirror 挂载区域。
- Modals：重命名与删除确认。

---

## 视觉与布局（轻盈清爽）

**布局原则**
- 左右分区清晰、间距充足、边框与阴影更弱。
- 操作区“主操作 + 次操作”分组，减少干扰。

**按钮排布**
- 主操作：新建（Primary）。
- 次操作：重命名/删除/刷新/换目录（Flat、低对比）。
- 操作区按组排列，组间弱分隔。

**样式方向**
- 背景更浅、边框更淡、圆角小而统一。
- 文本信息层级清晰（标题 > 状态）。

---

## 启动速度优化

**策略**
- 减少启动阶段重复的树渲染。
- 缩短首屏关键路径，避免不必要的同步计算。
- 通过 HeroUI Provider 全局关闭动画以减少初始开销。

**具体措施**
- 启动阶段只在打开文件后渲染树。
- Provider 使用 `disableAnimation`/`disableRipple` 减少交互动画。

---

## 数据流与错误处理

**数据流**
- AndroidFs RPC → 状态更新 → UI 渲染。
- 文件操作均在 UI 交互后触发。

**错误处理**
- RPC 异常统一转为状态提示。
- 启动失败显示 boot 提示，避免白屏。
